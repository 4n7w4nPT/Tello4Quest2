TELLO4QUEST2 — STATE & BACKLOG (v0.6)
=====================================
Snapshot for bootstrapping a new conversation. No version history - see README.


HARDWARE CONSTRAINTS
--------------------
- Tello consumer, SDK 1.3 (confirmed: `sdk?` returns "unknown command"). No GPS,
  no forward sensor, only a downward ToF + optical flow. Our dead reckoning is
  built on the same signal and drifts - not a substitute for real positioning.
- SDK 2.0 commands (setbitrate/setresolution/setfps) exist in the code but DO
  NOT work on this drone. They auto-lock in Video settings. Only useful on an
  EDU/Talent, where they'd be the single biggest quality win (they act at the
  source; everything else only displays better what the drone already sent).
- Quest 2: mobile SoC. Nothing needing a live neural net, unless the OS already
  provides it free (e.g. native hand tracking).
- No PC in the loop, by design. Standalone headset + drone + gamepad.
- The Tello's WiFi is 2.4 GHz only. Some packet-loss artefacts are physics.
- Oculus Go rejected as a target: toolchain dropped in 2020, no passthrough,
  3DOF breaks the world-locked UI. Different project, not a port.


PART 1 — CURRENT STATE
======================

VIDEO PIPELINE (rebuilt v0.5, most likely place to look if image or FPS look
wrong again)
- Reception: 4 MB UDP buffer, access-unit validation (bad start code = dropped,
  cheaper than decoding garbage), flush on headset resume.
- Decoding: gates on SPS *and* IDR. Drains the FULL output queue each Update
  with a ~2ms budget - MediaCodec delivers in bursts, so single-frame draining
  under-reported FPS ~3x and let latency climb all flight. Watchdog recreates
  the decoder if units arrive but nothing decodes for a few seconds.
- SPS parsed live: resolution, crop, and colour range/matrix when a VUI exists.
  This stream has NO VUI, so limited-range BT.601 is an assumption, not a
  measurement. Manual BT.709 override exists for visual comparison only.
- Colour bugs fixed: chroma was never range-expanded (~12% saturation lost),
  and gamma-encoded RGB was sRGB-encoded twice in a Linear project. Chroma
  siting (4:2:0 half-texel) also corrected.
- Presentation: Catmull-Rom bicubic, edge-preserving smoothing (reuses the
  sharpen pass's taps, so free), sharpening, night mode. All keyword-gated, so
  disabled effects cost zero samples.
- Stereo instancing added to the shader - it had NONE, so Single Pass Instanced
  rendered the left eye into both. Remember this if another custom shader gets
  added; it's easy to forget again.
- TelloVideoDisplay works on RUNTIME COPIES of both materials. Never write to
  the serialized `yuvMaterial`/`rgbaMaterial` asset refs - that's how stale
  playtest values got baked into the .mat permanently.
- Recorder: JNI objects cached across frames, waits for a keyframe, dimensions
  from the parsed SPS.

MAIN-THREAD HYGIENE (v0.6)
- Flight log buffered in a StringBuilder, flushed every 3s / on overflow / on
  close / on pause. Was doing a JNI write ~10x/sec all flight. Trade-off: a
  hard crash loses the last few seconds.
- PNG encoding on the thread pool via ImageConversion.EncodeArrayToPNG (takes a
  byte[], not a Texture2D). Pixel read and MediaStore write stay on main. Also
  fixed a leak: the YUV path created a Texture2D per photo nobody destroyed,
  while the RGBA path returned the decoder's own texture that must NOT be
  destroyed - TryCaptureSnapshotPixels now owns both cases.
- Single diagnostics master switch (TelloUiKit.DiagnosticsEnabled) gating all
  four per-component verbose flags.

UI / SCREENS
- Menu: pre-flight checklist centre, button cross right, D-pad cross left.
  D-pad LEFT opens the read-only Controls legend; the other three are drawn but
  explicitly empty. (Pre-v0.5 the West button showed "Controller" with no action
  bound - that's the mistake being avoided.)
- TelloControlMap is the single source of truth for the in-flight mapping. The
  Controls screen reads it entirely. It's also the data groundwork remapping
  will need.
- Settings: two pages (Video / Flight), ~47 params, graduated sliders + toggle
  switches, quality presets, conditionally-locked rows, per-page reset. Rows can
  be locked (isAvailable + lockedNote) or multiple-choice - both generic, reuse
  them rather than inventing another row type.
- Banners refresh on change, not every frame. Graphs bounded at 600 points with
  average-pair decimation (dropping every other point flattened the battery
  curve into straight segments). Mini-map no longer calls SetAsLastSibling once
  per trail point per frame - that was up to 500 canvas rebuilds/frame.
- Side bands pivot around their INNER edge, so nothing hides behind the video
  screen. Shared math in TelloUiKit.SolvePinnedPanelPosition.

SAFETY & GAMEPAD
- Auto-land on critical battery, altitude ceiling, crash detection, one-shot
  alerts with hysteresis.
- Takeoff (South) and Land (East) are SEPARATE buttons, each ignoring the press
  if already in that state - so the fix doesn't just move the problem to
  "repeated command answered with error, red Last cmd dot". Photo on West alone.

PROJECT SETTINGS THAT MATTER
- Color Space Linear, Single Pass Instanced, render scale ~1.1, no shadows,
  OVRManager Sharpen = Quality.
- Tracking Origin MUST stay Eye Level (not Floor Level): with passthrough,
  Floor Level makes Quest require a Roomscale Guardian and the app can fail to
  launch with no error at all. Do not let Meta's Project Setup Tool "fix" this.
- Materials and shader live in Assets/Materials/. TelloVideoRGBA must be
  URP/**Unlit** - it was found on URP/Lit in v0.5, meaning the RGBA fallback was
  being lit by the scene's directional light.

KNOWN OPEN ISSUES
- Gamepad sometimes never detected if paired AFTER launch. OS-level pairing
  succeeds, Unity's device list can stay empty. Not root-caused. Workaround:
  turn it on first.
- WiFi auto-connect: code present and compiling, but wired to nothing since West
  became Flight settings. If it ever returns it needs a new UI entry point.
- In-headset gallery: abandoned, no working approach on Quest's OS.
- BT.601 vs BT.709 unverified (no VUI in the stream).
- Macroblocks under packet loss: mitigated, not eliminated.


PART 2 — BACKLOG
================
S = small/contained · M = real feature work · L = needs a design pass first.

NEXT UP (v0.7, not locked): Flight History + Records, and/or button remapping
now that TelloControlMap exists. Three D-pad directions are free and are the
natural home for whichever screens get built.

SCREENS
- [S] Flight history - past flights (duration, distance, max altitude) parsed
  from the CSVs already being saved. Reuses the scrolling-list pattern.
- [S] Records - longest flight, highest altitude, top speed, total distance.
  DECIDE FIRST: separate persistent JSON, or recompute by re-parsing all CSVs?
  The second shares a CSV reader with Flight History - if both get built, write
  that reader once. Decide before coding, not during.
- [S] Artificial horizon line - pitch/roll are in telemetry and unused visually.
  Pairs naturally with horizon stabilisation below (same data, two uses).
- [M] Unit system, theme, localisation.

CONTROLS
- [M] Custom button remapping. Deliberately after the read-only legend - build
  what people can look at first, then decide if editing is actually wanted.
- [S] Flight profiles - saved speed/sensitivity/safety presets.
- [M] Head-orientation input, limited assist only (small yaw nudge, or gated
  behind a held button). NOT "head is a second stick" - the screen is
  world-locked precisely to avoid that discomfort. Needs a design pass.
- [M/L] Hand-gesture input via Quest's native hand tracking. No ML work needed
  from us, but real UX work to define a vocabulary that doesn't clash with
  normal use.

VIDEO
- [S] Quality preset polish - the presets shipped in v0.5 cover the image chain
  but not per-lighting colour correction. Worth revisiting after more flights.
- [S] Cross-fade when the watchdog recreates the decoder. Never seen in practice
  yet - worth watching for on a real WiFi dropout before building anything.
- [S] Digital zoom - crop+magnify the texture (distinct from the screen-size
  slider, which resizes the physical screen). Sits next to the crop-scale
  machinery already in the shader.
- [S] Surface FramesDroppedToCatchUpTotal and the watchdog recreate count
  somewhere visible - currently only reachable via Debug.Log.
- [M] Horizon stabilisation - counter-rotate the image using pitch/roll so the
  horizon stays level. High value in VR specifically (tilting horizon = motion
  sickness trigger).
- [M] Fixed Foveated Rendering + OVROverlay compositor layer, evaluated
  TOGETHER. An overlay layer is sampled once at native panel resolution instead
  of twice, which is the biggest sharpness win still available - but a
  compositor layer bypasses foveation entirely, so measuring one without the
  other misleads. Note it'd need to be an OVERLAY layer; passthrough already
  holds the underlay slot.
- [M] ArrayPool<byte> for reassembled access units (~1 MB/s of garbage). NOT
  done deliberately: the buffer crosses a thread boundary and goes to both the
  decoder and the recorder, so return-to-pool timing is the whole difficulty and
  a too-early return corrupts a frame silently. Only worth it if a profiler run
  actually shows the GC spikes mattering - which hasn't been done.
- [L] FSR 1.0 - low priority now that bicubic + smoothing + sharpening ship and
  are tunable. Only if that combination proves insufficient across more flights.

SAFETY / NAVIGATION
- [L] Return-to-home. HIGH RISK given Tello drift. Do not start before watching
  the mini-map across several real flights - if the drawn trail wanders, RTH
  isn't safe to build on it. The mini-map exists partly to make that visible.
- [M] Visual geofencing - same drift caveat, lower stakes (a warning, not
  automated flight).
- [M] Two-step takeoff confirmation.

INVESTIGATION
- [S/M] Gamepad-paired-after-launch. Three sessions of logs, no root cause.
  Likely needs a native Android InputManager.InputDeviceListener bridge, similar
  in spirit to TelloWifiConnector.java. Worth a dedicated session, not another
  quick C#-only attempt.


REJECTED (recorded so they don't get re-adopted)
================================================
From an external model's optimisation review. Accepted items shipped in v0.6.
- MERGING the per-panel Canvases into one: backwards. A Canvas is Unity's
  rebuild unit - one changed element rebuilds the WHOLE canvas. Splitting is the
  optimisation; merging would make the top banner's fps counter rebuild the
  graphs, mini-map and log with it. Do not do this.
- BitReader exceptions → TryRead: fine for cleanliness, but the SPS parses ONCE
  per session and exceptions only fire on a malformed one. Not a perf item.
- RefreshRows every frame in Settings: true, but Settings only opens on the
  ground. Zero flight impact.
- "Comments increase compiled size": wrong. Stripped at compile time.
- Prefabs instead of code-built settings UI: architecture preference, not
  optimisation. Lazy-building only the requested page is the sane middle ground
  if it ever matters.
- MSAA "on the video quad": not a thing - MSAA applies to the whole eye buffer.
- "Ensure the shader is Single Pass compatible": already fixed in v0.5. The
  reviewer had no project context and guessed at the right area.
